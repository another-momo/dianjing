# 运行时事实（install_skill 判断依据）

本文件描述产品运行时对 skill 的固定行为。这些机制你看不见也查不了（无源码视角），
照单执行即可；逐条都是你在工作流里要依赖的判断依据。

## 1. SKILL.md frontmatter 只认三键

| 键                         | 语义                                                        | 缺省               |
| -------------------------- | ----------------------------------------------------------- | ------------------ |
| `name`                     | skill 标识                                                  | 缺省回落父目录名   |
| `description`              | 触发信号（agent 自动触发与用户挑技能都靠它）                | 无                 |
| `disable-model-invocation` | 为 `true` 时不进自动触发清单，仍可 `/skill:<name>` 显式调用 | false = 进触发清单 |

- **其余一切键都被忽略**——`allowedTools` / `license` / `version` / `metadata` 等运行时零
  消费。所以 install_skill 只放行这三键：源文件含白名单外键时工具拒装并回报违规键清单，
  由你在 staging 剥除后重试，剥除清单写进 MIGRATION.md。
- `description` 缺失或全空白 = **不加载**（唯一的加载硬拒）。
- `name` 不合法时运行时只告警照载，所以合法性由 install_skill 硬拒兜底（≤64 字符、仅
  小写字母/数字/连字符、禁首尾与连续连字符）——别把「运行时会宽容」当放行理由。
- 模型永远看不到 frontmatter：skill 被调用时 frontmatter 整块剥掉，只有正文进上下文。

## 2. 加载与生效

- 两个加载层：**用户层** `workspace/.agents/skills/<name>/`（install_skill 的唯一写目
  标）与**内置层**（随产品发布，skill-installer 自己就在内置层）。
- **每开新会话重新扫描**两个层；当前存活会话不重载 → 新装的 skill **下一会话生效**。
- **撞名**：用户层同名会静默遮蔽内置层——所以 install_skill 撞内置名直接拒装；用户层
  同名需 `overwrite: true`（旧目录自动入备份）。
- 扫描跳过 `.` 开头目录与 `node_modules`；其余任何含 SKILL.md 的子目录都会被当 skill
  加载——用户层里不以 `.` 开头的残留副本/备份目录会占位撞名，这正是 install_skill 跳
  过隐藏件、查撞名的原因。
- 界面技能清单在打开「选择技能」或新会话时自动刷新——装完即见，不用重启应用。

## 3. 安装闸门的行为

- install_skill 弹**单动作确认卡**：卡上渲染将安装的文件清单与适配点摘要，用户批准才
  写盘。
- 没有批量/清单式确认形态——一次安装一张卡。
- **没有超时**：用户不点就一直等；用户拒绝、断连、取消都等于拒装（与 bash 命令授权同
  待遇）。无人值守场景下装不了就明说，不要假设会放行。
- 同一时刻全场最多一条待确认（确认卡与提问卡合计）——闸门等用户期间不要再发提问。

## 4. 别和 studio 其他资产混

`studio/` 下 workflows/profiles 等目录有自己的 frontmatter 格式（id/label 等另一套
键），与 skill 的 SKILL.md 平行不交叉——你处理的只有 §1 的三键面，别把其他目录的键
当 skill 键，也别给 skill 加那些键。
