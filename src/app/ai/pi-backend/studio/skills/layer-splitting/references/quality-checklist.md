# 质量检查清单

三层验收：单层生成后、组装后、阶段 4 强制验收。每层有明确的通过 / 失败判据与重试策略。

---

## 1. 单层生成后立即检查（每层独立）

阶段 1 batch 返回后，**逐层 `look` 该层节点**（不是只看容器整体）：

### 1.1 检查项

| 项 | 通过判据 | 不通过 |
|---|---|---|
| 单一目标 | 该层只含本层目标，无其他层元素混入 | 混入其他主体 / 背景 → 重试 |
| 透明 / 完整 | 普通层：目标以外区域无实心底色、无半透明噪点；背景层：整幅完整连续、被遮挡区已补全无破洞 | 普通层带实心底 / 背景层有洞有残影 → 重试 |
| 完整边缘 | 目标轮廓完整，无明显截断 / 缺口 | 边缘残缺 → 重试 |
| 原位关系 | 目标在原图坐标系下的位置与原图一致（容差 ~10%） | 漂移 > 10% → 重试 |

注意：`look` 对透明层会自动带设计上下文渲染（返回会声明）——判断"单一目标 / 无实心底"时区分"层自身的内容"与"上下文里透出的邻居"，别误判。

### 1.2 重试策略

- **不通过的项**：带相同 `replace_id` 单独 `generate_image` 重试 1 次（重试只含失败项）
- **重试时 prompt 微调**：
  - 位置漂移 → 加更具体的锚点 / 强调"原位"
  - 混入其他层 → 加强"排除范围"逐项点名
  - 透明失败（普通层带底） → 显式加"输出 PNG 透明通道"
  - 背景层有洞 / 残影 → 加强"抹除并补全"逐项点名 + "无破洞"
- **1 次重试仍败**：保留现状，记入阶段 4 报告，由用户决定下一步

### 1.3 不要做的事

- 不要静默调整 prompt 多轮试——单层最多 1 次重试，超出走用户决策
- 不要硬把"差不多"的层也接受——10% 容差是上限，不是目标
- 不要为加快进度跳过单层检查——所有层都查，漏 1 层就是组装后必现的瑕疵

---

## 2. 组装后门控

骨架与生图 / 文字施工完成后：

### 2.1 检查项

1. **母子结构**：`describe` 容器——所有层是容器子节点，容器本身与原图同位同尺寸
2. **层级顺序**：容器内自底向上 = 背景 → 非文字层按遮挡 → 文字层最顶
3. **同位叠放**：所有非文字层在容器局部 `@ (0, 0) W × H`
4. **遮挡关系**：前景盖主体、文字盖所有非文字——符合原图视觉（原图明确遮挡文字的个别情况除外）
5. **原图保留**：原图节点未被破坏 / 删除 / 修改——与阶段 0 读到的元数据一致

### 2.2 失败处理

| 失败 | 修复 |
|---|---|
| 层级顺序错 | `reparent_node` 重排——它只能把节点挂到目标父级的**末尾**（最顶），所以按自底向上目标顺序依次 reparent（先背景、再主体……），全部过一遍即完成排序 |
| 非文字层不在容器局部 (0,0) | `update_node` 设 `x=0, y=0, width=W, height=H` |
| 层跑到容器外 | `reparent_node` 挂回容器，坐标改容器局部 |
| 原图被破坏 | 立即停手告诉用户——若破坏来自 `generate_image` 的 replace 覆盖，覆盖前有自动快照、仍作 reference 可找回；删除 / 属性改动则不可恢复 |

---

## 3. 阶段 4 强制验收（漂移检查）

**不可省略**。漂移是端到端最大不确定项——生图模型对 prompt"原位重绘"的遵从度非 100%。

### 3.1 逐层 look 对照原图

每层独立 `look`，与原图同一区域对照：

- **位置**：目标位置与原图对应区域一致（容差 ~10%）
- **比例**：大小 / 长宽比与原图一致
- **细节**：内部细节（高光、阴影、纹理）保持

### 3.2 显隐检查

逐层 `update_node` 切 `visible`：

- 关掉一层后，剩余画面应仍是一个合理画面（不暴露不该出现的元素 / 不漏关键内容）
- 切换后 `look` 视觉对比，确认无溢出 / 错位
- 整体对照：容器 visible 切掉看原图、切回看拆分结果，两画面应几乎一致

### 3.3 场景树确认

`describe` 容器子树：

- 节点数 = 分层规划数
- 命名 = 阶段 0 起的语义名
- 层级顺序 = 组装顺序
- 原图节点仍存在，属性未变

### 3.4 漂移容差与处理

**~10% 位置容差**是工程预期，不是设计目标。

| 漂移量 | 处理 |
|---|---|
| < 5% | 通过 |
| 5% ~ 10% | 通过 + 在汇报中标注（用户可选微调） |
| > 10% | **失败**——定向重试 1 次 |
| 重试仍 > 10% | **告知用户漂移事实 + 保留现状**——不静默调整，由用户决定微调 / 重做 / 接受 |

### 3.5 文字层漂移

文字层坐标是 agent 自己设的——漂移 = 直接 `update_node` 校正（不需要重生成）。

- > 5% 漂移：必须校正
- 字号不准：`update_node` 调 `font_size`
- 字体不准：`set_font` 调 `family`
- 颜色不准：`set_fill` 调 `color`（hex）

### 3.6 验收完成汇报模板

阶段 4 通过后告诉用户：

```
图层拆分完成。容器"<原图名>·拆分"内含 N 个非文字层 + M 个文字层。

非文字层：背景 / 主体 / 前景 / Logo / 边框光效
  - 背景：通过
  - 主体：通过（轻微漂移约 3%，已标注）
  - 前景：第 2 次重试后通过
  - Logo：通过
文字层：text_1 / text_2 / text_3
  - text_1：通过（字体"待确认"）
  - text_2：通过
  - text_3：通过

原图节点保留未动，可隐藏容器对比。场景树可通过 describe 查看。
```

---

## 4. 失败上报纪律

任何阶段失败（重试 1 次仍败、缺 key、视觉模型读不准文字等），**必须**显式告诉用户：

- **发生了什么**——具体哪一层 / 哪一步
- **已经做了什么**——已重试 / 已 fallback / 已放弃
- **建议的下一步**——用户决策选项

不要静默吞错、不要自动降级方案顶替、不要隐瞒部分失败。
