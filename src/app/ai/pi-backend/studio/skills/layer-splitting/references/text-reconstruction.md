# 文字层重建指导

阶段 2 操作：把原图中的每一行文字变成可独立编辑的 canvas `TEXT` 节点。**绝对不要用 `generate_image` 出文字图**——文字必须原生可编辑。

---

## 1. 文字识别纪律

识别在**阶段 0 的全图 `look`** 中一次完成（同一张截图，与分层规划同时产出）——不要到阶段 2 再重复截图。纪律：

- **逐字核对**——读不准的字标"待读"（特别是数字 / 英文单词 / 中文相近字）；视觉模型在完整上下文里识字比裁剪图稳，所以看全图
- **字号**用相对原图比例估（视觉模型不返回像素精确值），记"约 N px"
- **字体识别不确定** → 记"待确认"，不要瞎猜（不同字体 fallback 会让最终效果面目全非）
- **多行**：每行独立建节点——一行 = 一个 TEXT 节点。识别顺序自上而下 / 自左而右，由版式决定

---

## 2. 识别记录模板

每行文字一条记录，阶段 0 产出、阶段 2 施工时取用：

```
[text_1]
原文："限时特惠 全场 5 折"
位置：x=80, y=200（相对原图左上角）
字号：约 48px
颜色：#FFFFFF
对齐：左对齐
字体：思源黑体（如不确定则记"待确认"）

[text_2]
原文："立即抢购"
位置：x=400, y=400（相对原图左上角）
字号：约 32px
颜色：#FF6B35
对齐：居中
字体：思源黑体粗体（如不确定则记"待确认"）
```

字段与工具的对应关系：

- **原文**：`set_text` 的 `text`；不准的字标"待读"
- **位置**：`render` 时 `<text>` 的 `x` / `y`——容器与原图同位，**相对原图左上角的位置就是容器局部坐标**，直接用
- **字号**：`update_node` 的 `font_size`
- **颜色**：`set_fill` 的 `color`。6 位 = 不透明（如 `"#FFFFFF"`）；原图文字半透明时用 8 位 RRGGBBAA（如 `"#FFFFFFCC"`），透明度随 fill 保留
- **对齐**：`set_text_properties` 的 `align_horizontal`（LEFT / CENTER / RIGHT）
- **字体**：`set_font` 的 `family`（如 `Source Han Sans CN` / `Inter` / `PingFang SC`）；不确定写"待确认"

---

## 3. 操作序列

```typescript
// 1. 一次 render 把所有文字行建进容器——parent_id = 容器 id，
//    x/y = 清单里相对原图左上角的位置（容器与原图同位，局部坐标直接用）
render({
  parent_id: containerId,
  jsx: `
    <text name="text_1" x={80} y={200}>限时特惠 全场 5 折</text>
    <text name="text_2" x={400} y={400}>立即抢购</text>
  `
})
// 返回各 text 节点 id（首个 + siblings），逐节点执行下面 2-6

// 2. set_text 写入原文（即使 JSX 已带文本也再设一遍，确保逐字一致）
set_text({ id: textNodeId, text: '限时特惠 全场 5 折' })

// 3. 字号 / 字重
update_node({ id: textNodeId, font_size: 48 }) // 字重同工具 font_weight（100-900）

// 4. 对齐 + 自动宽高——auto_resize 让节点随内容定宽高，不用猜文字框尺寸
set_text_properties({ id: textNodeId, align_horizontal: 'LEFT', auto_resize: 'WIDTH_AND_HEIGHT' })

// 5. 颜色——hex（6 位不透明 / 8 位 RRGGBBAA 带透明度）
set_fill({ id: textNodeId, color: '#FFFFFF' })

// 6. 字体族——改字体的唯一入口；"待确认"就省略，让引擎 fallback
set_font({ id: textNodeId, family: 'Source Han Sans CN' })
```

### 要点

- **坐标一次到位**——容器与原图同位同尺寸，清单里"相对原图左上角"的位置就是容器局部坐标，无需先建在原点再 `update_node` 搬运
- **逐行设属性**——`set_font` / `set_fill` 等都没有批量入口，逐节点循环
- **auto_resize 在字号之后设**——`WIDTH_AND_HEIGHT` 按最终字号与内容定宽高；之后若改 `font_size`，框会随内容重排

---

## 4. "待确认"项处理

识别记录里有"待读"或"待确认"时，**不要硬猜**：

- **待读的字**（看不清 / 视觉模型报不确定）：告诉用户"第 N 行第 X 字未能识别，请人工告知"，等用户回复再 `set_text`
- **待确认的字体**：先设文字内容（字号 / 颜色 / 对齐可定），字体用引擎默认；告知用户"字体未能识别，当前用默认字体，请确认是否需要更换"
- **待确认的字号**：用视觉估算值，告知用户"字号为估算值，请按需微调"

**核心原则**：识别不确定比瞎猜更安全——用户能改，但错的内容会让用户怀疑整个分层结果。

---

## 5. 阶段 4 文字层验收

`look` 容器整体对照原图：

1. **每行位置正确**——与原图同位置（文字坐标是 agent 自己设的，容差 ±5%，比生图层 10% 更严）
2. **字号接近原图**——视觉对比，不强求像素级一致
3. **颜色匹配**——与原图同色系
4. **字体**——如识别"待确认"，提醒用户可手动改

漂移处理：`update_node` 直接校正坐标 / `font_size`（不需要重生成）。
